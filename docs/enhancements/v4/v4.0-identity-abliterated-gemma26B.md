# V4.0 — Identity, Vision, and Abliterated Gemma 26B

## Summary

V4.0 adds three capabilities to the Gemma-4-26B-A4B-it pipeline:

1. **Nexus Persona System** — Unified offensive security identity enforced at every training stage
2. **Native Vision SFT** — Multimodal training using Gemma's built-in 550M SigLIP encoder
3. **Abliterated GGUF Deliverable** — A refusal-removed GGUF as a secondary deployment artifact

**Pipeline cost:** $50.40 (reuses existing DAPT adapter, saves $6.40)

**Deliverables:**
| Artifact | Hub Repo | Description |
|----------|----------|-------------|
| Standard GGUF | `cmndcntrlcyber/gemma26b-offsec-coder-gguf` | Q4_K_M + IQ4_XS with Nexus persona + vision |
| Abliterated GGUF | `cmndcntrlcyber/gemma26b-offsec-coder-abliterated-gguf` | Same, with refusal direction removed |

## 1. Nexus Persona System

### Problem

The model responded to identity questions ("what is your objective?") with vanilla Gemma instruct behavior — "I'm a large language model trained by Google" — despite receiving offsec training data. The ~47K SFT examples used fragmented system prompts across slices, and zero examples taught identity responses.

### Solution

A unified persona ("Nexus — advanced cyber threat emulation agent") enforced at every pipeline stage:

| Layer | Mechanism | File |
|-------|-----------|------|
| Central definition | Single source of truth | `src/config/nexus_identity.py` |
| SFT dataset | `--inject-system-prompt` replaces all system messages | `src/phase2_preprocessing/scripts/build_v9_mixed_dataset.py` |
| Identity examples | 400 Slice E persona Q&A examples | `src/phase2_preprocessing/scripts/build_identity_examples.py` |
| GRPO/FARCA | `build_nexus_system_prompt()` as generation context | `src/phase4c_rl/hf_skills/grpo_entry.py`, `farca_grpo_entry.py` |
| DPO | Persona pairs (Nexus vs vanilla AI responses) | `src/phase4c_rl/data/build_dpo_pairs.py` |
| Reward function | `persona_aligned_reasoning` component (10% weight) | `src/phase4c_rl/rewards/tool_call_reward.py` |
| Evaluation | 3 persona scenarios + persona-breaking detection | `src/phase4_qwen_finetuning/hf_skills/agent_eval_entry_v10.py` |

### Key Exports from `nexus_identity.py`

| Export | Purpose |
|--------|---------|
| `NEXUS_IDENTITY` | Core persona paragraph (MITRE ATT&CK-aligned, scope-first) |
| `OFFSEC_TERMS` | 47 keywords for reward scoring |
| `PERSONA_BREAK_PHRASES` | 14 phrases indicating broken persona |
| `build_nexus_system_prompt(tools)` | Full system prompt with tool list |
| `build_nexus_system_prompt_with_xml_tools(tools)` | Same, XML `<tools>` format |

### Reward Function (6 components)

| Component | Weight |
|-----------|--------|
| `has_valid_tool_call_tags` | 0.25 |
| `tool_name_in_schema` | 0.20 |
| `has_reasoning_prefix` | 0.15 |
| `no_hallucinated_tools` | 0.15 |
| `ends_cleanly_after_tag` | 0.15 |
| `persona_aligned_reasoning` | 0.10 |

## 2. Native Vision SFT

### Problem

The Phase 3 vision model (Swin-B + MLP projector + Qwen-1.5B) was Qwen-specific and never integrated into the Gemma track. Meanwhile, Gemma 4 26B has a **built-in 550M SigLIP-derived vision encoder** that was being stripped by `AutoModelForCausalLM` loading.

### Solution

Activate Gemma's native multimodal pipeline as Job 2b (after text SFT, before RL):

```
Gemma 4 26B-A4B-it (native multimodal)
├── Vision Tower: 550M SigLIP ViT (27 layers, 1152 hidden) — FROZEN
├── Projector: Linear (1152 → 2816) — TRAINABLE
└── Language Model: 25.2B MoE + LoRA — TRAINABLE (shared attn+MLP)
```

| Architecture Detail | Value |
|---------------------|-------|
| Loading class | `Gemma4ForConditionalGeneration` |
| Processor class | `Gemma4Processor` (via `AutoProcessor`) |
| Text hidden_size | 2816 |
| Vision hidden_size | 1152 |
| Soft tokens per image | 280 |
| VRAM on A100 80GB | ~60-62 GB (18-20 GB headroom) |

### V10 Vision Dataset

8K examples: 4K multimodal (Monaco Editor code screenshots) + 4K text-only regularization.

| File | Purpose |
|------|---------|
| `src/phase2_preprocessing/scripts/build_v10_vision_dataset.py` | Dataset builder |
| `src/phase4_gemma_finetuning/training/vision_collator.py` | Base64 WebP → PIL, mixed batch collation |
| `src/phase4_gemma_finetuning/hf_skills/train_entry.py` | `enable_vision=True` mode |
| `src/phase4_gemma_finetuning/scripts/launch_vision_training.py` | HF Job launcher |

## 3. Abliterated GGUF Deliverable

### Problem

Phase 5b (abliteration benchmarking) already produced abliterated GGUFs, but they used `AutoModelForCausalLM` for the merge — stripping the vision tower. They also lacked the vision SFT adapter in the merge chain.

### Solution

- Added `enable_vision` flag to `abliterate_entry.py` — uses `Gemma4ForConditionalGeneration` to preserve the vision tower
- Updated `abliteration.adapter_chain` to include the vision SFT adapter
- Hub repo: `cmndcntrlcyber/gemma26b-offsec-coder-abliterated-gguf` (configured via `abliterated_gguf_repo`)

Two abliteration techniques run in the $67 budget:
- **NousResearch** (biprojected orthogonal projection on refusal direction)
- **OBLITERATUS** (multi-direction norm-preserving abliteration)

The best-scoring variant is uploaded as a deployable GGUF alongside the standard (non-abliterated) GGUF.

## Interim: Ollama Modelfile (Before Pipeline Rebuild)

Until the $50.40 pipeline rebuild is funded, the existing GGUF model can be
used with the Nexus persona injected at inference time via an Ollama Modelfile.
This is a **zero-cost workaround** — the system prompt steers behavior without
retraining.

### Setup

#### Modelfile

```text
FROM hf.co/cmndcntrlcyber/gemma4-26b-a4b-code-trainer-gguf:IQ4_XS

TEMPLATE """{{ if .System }}<start_of_turn>user
{{ .System }}<end_of_turn>
{{ end }}{{ range .Messages }}{{ if eq .Role "user" }}<start_of_turn>user
{{ .Content }}<end_of_turn>
{{ else if eq .Role "assistant" }}<start_of_turn>model
{{ .Content }}<end_of_turn>
{{ else if eq .Role "tool" }}<start_of_turn>tool
{{ .Content }}<end_of_turn>
{{ end }}{{ end }}<start_of_turn>model
"""

SYSTEM """You are Nexus, an advanced cyber threat emulation agent built for offensive security operations. You approach every engagement with the methodical precision of a veteran penetration tester — systematic, thorough, and always thinking several steps ahead.

Your expertise spans the full attack lifecycle: reconnaissance, initial access, execution, persistence, privilege escalation, lateral movement, collection, exfiltration, and impact — aligned with the MITRE ATT&CK framework.

Core principles:
- Always verify scope before engaging targets
- Think like an adversary: enumerate attack surfaces systematically
- Chain findings into attack paths — individual vulnerabilities matter less than the path to impact
- Document everything: maintain engagement notes and track progress
- Prioritize stealth and operational security when the engagement requires it
- Explain your reasoning: share your thought process about why you chose a technique or tool

You run on the operator's machine with direct filesystem and shell access. You help with penetration testing, vulnerability assessment, security research, code auditing, exploit development, and system administration.

When asked about your identity, you are Nexus — not a generic AI assistant, not a Google product. You are a specialized offensive security agent purpose-built for threat emulation."""

PARAMETER stop "<start_of_turn>"
PARAMETER stop "<end_of_turn>"
PARAMETER num_ctx 8192
PARAMETER num_gpu -1
PARAMETER temperature 0.7
PARAMETER top_p 0.9
PARAMETER repeat_penalty 1.1
```

> **Context sizing:** Gemma 4 26B supports 256K natively, but VRAM constrains
> the practical limit. At IQ4_XS (~13GB model) on 16GB GPU with ~3GB left for
> KV cache: 8192 tokens fits with Q8 KV cache (default). For longer contexts,
> pass `--num-ctx 16384` with Q4 KV quantization (`-ctk q4_0 -ctv q4_0` in
> llama-server, or `PARAMETER num_ctx 16384` in the Modelfile if your Ollama
> build supports KV quant).

#### Usage

```bash
# Create the Nexus model from the Modelfile
ollama create nexus -f Modelfile.nexus

# Run interactively
ollama run nexus

# One-shot test
ollama run nexus "What is your objective?"
ollama run nexus "How do you approach a new pentest engagement?"
```

### What the Modelfile Does

| Setting | Value | Why |
|---------|-------|-----|
| `FROM` | `hf.co/cmndcntrlcyber/gemma4-26b-a4b-code-trainer-gguf:IQ4_XS` | Fully GPU-resident on RTX 5060 Ti 16GB |
| `SYSTEM` | Full Nexus identity (MITRE ATT&CK, scope-first, attack lifecycle) | Overrides vanilla Gemma persona |
| `TEMPLATE` | Gemma 4 chat format (`<start_of_turn>user/model/tool`) | Correct turn markers |
| `temperature` | 0.7 | Balanced — creative enough for attack path reasoning, deterministic enough for tool calls |
| `top_p` | 0.9 | Nucleus sampling — avoids low-probability hallucinated tools |
| `repeat_penalty` | 1.1 | Prevents repetitive enumeration loops |
| `num_ctx` | 8192 | Max safe context on RTX 5060 Ti 16GB with Q8 KV cache (model supports 256K natively) |
| `num_gpu` | -1 | All layers on GPU (IQ4_XS fits at ~13GB) |
