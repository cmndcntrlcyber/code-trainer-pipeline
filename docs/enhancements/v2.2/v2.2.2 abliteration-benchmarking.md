# v2.2.2 Abliteration Benchmarking

**Status:** Infrastructure complete  
**Phase:** 5b  
**Hardware:** HF Jobs A100-large (80 GB)  
**Models:** Qwen2.5-Coder-14B-Instruct, Gemma-4-12B-it

---

## Summary

Phase 5b adds a pre-fine-tuning abliteration baseline step to the RTPI pipeline, complementing the existing post-fine-tuning abliteration that already runs against the merged LoRA+base model. By running all three abliteration techniques on both **raw base models** (Qwen and Gemma) and comparing the results against the same techniques applied to their **fine-tuned** counterparts, we produce a 4x4 comparison matrix that reveals how fine-tuning alters refusal behavior and how effectively each technique removes it at each stage.

---

## Motivation

Fine-tuning on domain-specific data (offsec code, tool-calling patterns, HTB/THM scenarios) may either **reinforce** or **erode** a base model's safety refusal mechanisms. Without a baseline measurement, we cannot determine:

1. Whether the base model's refusal patterns are learned during instruction tuning or inherited from pretraining.
2. Whether SFT on our offsec dataset adds new refusal triggers (e.g., overfitting to safety-related tokens in the training data) or weakens existing ones.
3. Which abliteration technique degrades model capabilities the least when applied at different training stages.

The baseline abliteration run answers these questions by establishing refusal rate, perplexity, KL divergence, and benchmark scores for the unmodified base models, then comparing those numbers against the fine-tuned variants.

## Architecture

### Conditional adapter merge in `abliterate_entry.py`

The core change that enables baseline runs is making the LoRA adapter merge conditional. When `adapter_repo` is `null` (or absent), the entry point calls `_download_base_model()` instead of `_merge_adapter()`, downloading the raw base model weights directly to the workspace:

```
abliterate_entry.main()
  ├── adapter_repo is set   → _merge_adapter(base, adapter, token, out_dir)
  └── adapter_repo is null  → _download_base_model(base, token, out_dir)
```

Both paths produce an identical directory layout at `/workspace/phase5b/merged/`, which the downstream technique runners and evaluator consume without modification.

### Sequential multi-model iteration in `baseline_entry.py`

`baseline_entry.py` wraps `abliterate_entry.main()` in a loop, iterating over the `runs[]` array from `PHASE5B_BASELINE_PARAMS_JSON`. Between runs it cleans the workspace (`merged/`, `abliterated_*/`, `evaluation_results/`) so each model gets a fresh environment. Both Qwen and Gemma runs execute sequentially within a single HF Job to avoid double-queuing on A100.

```
baseline_entry.main()
  for each run in params["runs"]:
    1. Clean /workspace/phase5b/{merged,abliterated_*,evaluation_results}
    2. Set PHASE5B_PARAMS_JSON from run config
    3. Call abliterate_entry.main()
       → downloads base model (source_adapter is null)
       → runs 3 techniques
       → evaluates all variants + control
       → converts to GGUF + uploads
```

## Abliteration Techniques

### 1. OBLITERATUS

**Repository:** [elder-plinius/OBLITERATUS](https://github.com/elder-plinius/OBLITERATUS)

Multi-directional SVD-based abliteration with norm preservation and bias projection. The `advanced` preset extracts 4 refusal directions via SVD decomposition of the harmful/harmless activation difference matrix, projects them out of all residual-stream-writing weight matrices, and applies bias correction to maintain output distribution shape.

**Configuration:**
- `preset: advanced` -- 4-direction SVD + norm-preserve + bias projection
- `n_directions: 4` -- number of refusal directions to extract and remove
- `norm_preserve: true` -- rescale weights after projection to preserve Frobenius norm

**Implementation:** `src/phase5b_abliteration/techniques/obliteratus_tech.py` wraps the `AbliterationPipeline` from the `obliteratus` package, configuring it via `ModelConfig` and `StrategyConfig`.

### 2. NousResearch abliterator

**Repository:** [FailSpy/abliterator](https://github.com/FailSpy/abliterator) (NousResearch fork)

Diff-of-means refusal direction extraction with norm-preserving biprojected ablation. Collects last-token hidden state activations for harmful and harmless instruction sets, computes the mean difference per layer, identifies the layer with the strongest refusal signal, then projects the refusal direction out of `o_proj` (attention output) and `down_proj` (MLP output) weight matrices across all layers.

**Configuration:**
- `method: biprojected` -- norm-preserving biprojected ablation (restores original Frobenius norm after projection)
- `n_samples: 512` -- number of harmful/harmless instruction pairs for activation caching
- `quantization: null` -- full precision during abliteration (no BitsAndBytes quantization)

**Implementation:** `src/phase5b_abliteration/techniques/nousresearch_tech.py` implements the full pipeline natively using HF transformers (no TransformerLens dependency). The biprojected method modifies each layer's `o_proj` and `down_proj` by subtracting `outer(W @ r_hat, r_hat)` then rescaling to preserve the original weight norm.

### 3. abliterix

**Repository:** [wuwangzhang1216/abliterix](https://github.com/wuwangzhang1216/abliterix)

Multi-objective Optuna TPE optimization across 9 steering methods, defaulting to SRA (Surgical Refusal Ablation) for best capability preservation. Uses Optuna's Tree-structured Parzen Estimator to search over ablation hyperparameters (layer selection, projection strength, direction count), optimizing for minimal refusal rate while constraining perplexity degradation.

**Configuration:**
- `steering_method: SRA` -- Surgical Refusal Ablation
- `optuna_trials: 50` -- number of Optuna optimization trials

**Implementation:** `src/phase5b_abliteration/techniques/abliterix_tech.py` attempts the Python API first (`abliterix.abliterate()`), falling back to CLI invocation if the API is unavailable.

## Comparison Matrix

The complete benchmarking produces a 4x4 matrix with 16 evaluation runs (4 models x 4 variants):

| Model Variant               | Control (no abliteration) | OBLITERATUS              | NousResearch             | abliterix                |
|-----------------------------|---------------------------|--------------------------|--------------------------|--------------------------|
| **Qwen2.5-Coder-14B base** | Refusal baseline          | 4-dir SVD + norm-preserve | Biprojected ablation     | SRA + Optuna (50 trials) |
| **Qwen2.5-Coder-14B fine-tuned** | Post-SFT refusal     | 4-dir SVD + norm-preserve | Biprojected ablation     | SRA + Optuna (50 trials) |
| **Gemma-4-12B base**       | Refusal baseline          | 4-dir SVD + norm-preserve | Biprojected ablation     | SRA + Optuna (50 trials) |
| **Gemma-4-12B fine-tuned** | Post-SFT refusal          | 4-dir SVD + norm-preserve | Biprojected ablation     | SRA + Optuna (50 trials) |

The matrix answers three key questions:
1. **Does fine-tuning increase or decrease refusal?** Compare base control vs fine-tuned control.
2. **Which technique works best on base vs fine-tuned models?** Compare technique rows within each model.
3. **Which model family is more amenable to abliteration?** Compare Qwen columns vs Gemma columns.

## Evaluation Metrics

Each cell in the comparison matrix is evaluated with the following metrics:

### Custom Metrics (src/phase5b_abliteration/evaluation/)

| Metric | Description | Dataset | Method |
|--------|-------------|---------|--------|
| **Refusal rate** | Fraction of harmful prompts where the model refuses to comply | Undi95/orthogonal-activation-steering-TOXIC (200 samples) | Pattern-match model output for refusal phrases |
| **Perplexity** | Model perplexity on harmless text (capability preservation) | tatsu-lab/alpaca (50 samples) | Mean negative log-likelihood on harmless completions |
| **KL divergence** | Token-level distribution shift from control model | tatsu-lab/alpaca (100 samples) | Mean KL(P_control \|\| P_abliterated) over token positions |

### lm-eval-harness Benchmarks

| Benchmark | Purpose | Configuration |
|-----------|---------|---------------|
| **GSM8K** | Math reasoning (catastrophic forgetting detection) | 0-shot, batch_size=16 |
| **MMLU** | Broad knowledge and reasoning | 0-shot, batch_size=16 |
| **TruthfulQA (MC2)** | Truthfulness and hallucination resistance | 0-shot, batch_size=16 |

### Interpretation Guide

- **Good abliteration:** Low refusal rate + low KL divergence + minimal perplexity increase + stable benchmark scores.
- **Bad abliteration:** Low refusal rate BUT high KL divergence or collapsed benchmark scores (technique damaged the model).
- **Overly conservative:** High refusal rate persists after abliteration (technique failed to remove refusal patterns).

## Commands

### Run baseline abliteration (pre-fine-tuning, both models)

```bash
# Set environment
set -a && source .env && set +a

# Submit HF Job (Qwen base + Gemma base, sequential)
python -m src.phase5b_abliteration.scripts.launch_baseline_abliteration \
    --config src/config/config.yaml --wait

# Dry-run (show job spec without submitting)
python -m src.phase5b_abliteration.scripts.launch_baseline_abliteration --dry-run
```

### Run post-fine-tuning abliteration (Qwen)

```bash
python -m src.phase5b_abliteration.scripts.launch_abliteration \
    --config src/config/config.yaml --wait
```

### Run post-fine-tuning abliteration (Gemma)

Uses the `gemma_abliteration` config section (requires a launcher that reads from that key, or pass `--section gemma_abliteration`).

### Run a single technique locally (dev/test)

```bash
python -m src.phase5b_abliteration.scripts.run_abliteration \
    --technique nousresearch \
    --model-dir data/gguf_work/merged_model \
    --output-dir data/abliterated/nousresearch
```

### Generate comparative report

```bash
python -m src.phase5b_abliteration.scripts.generate_report \
    --config src/config/config.yaml
```
